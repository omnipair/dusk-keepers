# Keeper repository guardrails

- `captured` protocol locks allow fixtures, shadow runtimes, and Surfpool work only. A live runtime must require `frozen`, verify every artifact/fingerprint, and pass the explicit live-release gate. Never weaken this check to unblock deployment.
- Local live preparation on 2026-11-19 follows the owner's instruction to prepare the new mainnet deployment and their earlier instruction to skip release tests. The separate `mainnet-2026-11-19` decision is recorded in `docs/evidence/mainnet-release-waiver.json`; the former `mainnet-2026-11-14` waiver remains unchanged in its release archive. Freeze only these verified artifact pins without representing the skipped matrix or mainnet canary as passed. Runtime deployment, simulation, fee/reserve, lease and journal checks remain required. Future revisions require their own release decision.
- The owner also selected private-key files for the local mainnet launcher. Explicit `SIGNER_PROVIDER=local` is supported for that use; KMS remains available for hosted services. Never place a real key in the repository or print its contents.
- User-authorized local devnet testing may explicitly opt in with `KEEPER_ALLOW_CAPTURED_DEVNET=1`: verify devnet genesis and exact captured deployment, discover all active supported markets, retain signing limits and PostgreSQL journaling, and recheck deployment before submission. This exception never freezes a captured lock or authorizes another network.
- JSON Schemas, protocol artifacts, and golden fixtures are the cross-language contract. Rust and TypeScript implementations stay native and must pass the same fixtures; do not share implementation source across languages.
- Indexer data may discover candidates but can never authorize execution. Re-read every safety-critical account through direct RPC immediately before evaluation, simulation, and any re-sign.
- Persist the work item, ordered attempt events, signing generation, and outcome in PostgreSQL. Acquire the distributed lease before signing. Live mode must pause when either store is unavailable; never fall back to process-local locking.
- Run lending, leverage/order execution, hLP recovery, revenue auctions, lifecycle, and sentinel as separate services. The lending service owns ordinary and emergency liquidation; it selects a route before durable submission and never falls back after a submission error. Signing services use distinct wallets and remote-signer policies.
- Never store seed phrases, keypair JSON, private keys, database credentials, RPC credentials, or signer tokens in source, logs, health output, fixtures, or plaintext environment templates.
- Blockhash expiry before submit may create a new signing generation only after revalidation. An unknown submitted transaction must be reconciled to landed or definitively not landed before any re-sign.
- `protocol/keeper-instructions.v1.json` and its envelope fixtures are generated from the pinned IDLs. Never hand-edit them; regenerate and review the semantic diff. Validation proves instruction shape, not economic eligibility or account freshness.
- `protocol/keeper-account-resolution.v1.json` and adapter codec fixtures are generated from the pinned IDLs. Keep Rust Borsh/PDA code and TypeScript Borsh/PDA code native and independent; decimal-string `u64` wire values, exact seed encoding, bumps, and static addresses must match the shared vectors.
